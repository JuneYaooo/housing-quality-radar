# 数据入口与采样

## 入口选择

默认优先级：**宿主 computer use → 宿主浏览器 → opencli → TikHub REST → MediaCrawler**。这是参考项目的数据源路由约定，不代表任何方式保证安全或稳定。用户已指定来源时遵从其偏好；本地材料直接分析，不为满足顺序额外联网。宿主明确要求其他工具优先时遵从宿主指令。

先自检可用能力，再尝试一个与任务相关的最小读取。命令存在、健康检查通过或接口出现在目录，只证明工具可发现；真实返回有效帖子才证明该项能力本轮可用。按搜索、详情、账号历史、图片/视频、评论分别记能力，不因搜索成功就宣称全链路可用。上级入口成功后仅针对缺失字段选择后级，不把所有来源都跑一遍。

具体命令、版本边界和退出条件见 [source-adapters.md](source-adapters.md)。本 Skill 不捆绑 opencli、TikHub 或 MediaCrawler，也不自动运行参考仓库安装器。已有工具直接复用；新安装、付费调用或新账号登录缺必要授权/配置时说明具体缺项，沿可用且已授权的路径继续。既有付费额度和来源授权不重复询问。没有数据入口时分析用户导出、帖子内容及截图，链接不可读就保留为待采集。

未登录访问原帖被重定向到 `error_code=300031`（“当前笔记暂时无法浏览”）属于访问限制，记 `post_inaccessible`，不能记成删除或已成交。登录失效、验证码、403、429、访问限制出现后保存进度并停止受影响入口，记录原因；不使用代理轮换、验证码破解或提取其他应用凭证。零搜索结果不是访问失败的替代状态。可改用已有导出或用户提供内容，不反复重试受限请求。

网页搜索可补充发现链接，但摘要只作为线索；未进入原帖的结果标 `snippet_only`，不能当成全文证据。不要承诺全站、全量或稳定覆盖。

## 搜索矩阵

使用配置中的城市、小区标准名、别名与常见简称；同名小区必须结合城市、区县确认。分别组合：

- 租房：小区＋租房/整租/转租/房东直租/已租，区域＋户型＋预算词。
- 买房：小区＋出售/二手房/业主直售/降价/已售，区域＋户型。
- 区域补充：地铁站、片区和相邻小区；单独标记是否超出目标范围。

接口不支持组合词时先用完整小区名或有区分度的别名搜索，再在结果中筛选城市和租售类型；不套用参考项目自媒体场景的“所有词限制 2–4 字”规则。

搜索结果页逐条记录可见范围、排序方式、查询词和采样时间；有最新排序时优先采集最新，同时抽样相关排序。不要把搜索排名变化当房源变化。不以低价、精装、个人号等标签提前过滤全部原始样本。

初轮默认目标为 50 条相关帖子和 10 个相关账号，每账号最多回看 20 条相关可见历史；预算、访问限制和样本稀疏可提前结束。这是工作量上限/目标，不是统计充分性的保证；报告实际完成数。后续轮询优先近期新增、重点小区、已有高匹配候选和待核验异常，再补充新账号，防止只跟老账号形成偏差。

## 帖子采集顺序

区域/小区关键词搜索 → 记录原始链接、帖子 ID、发布时间和作者 → 轻筛区域及租售类型 → 读取候选正文与媒体 → 去重并提取账号集合 → 查公开主页和近期历史 → 有疑点的候选补相关评论 → 保存观察后分析。先完成区域及账号基线，再给房源排序。

已有账号链接可从主页/历史开始，但缺区域搜索时只交付该账号样本分析；已有单帖链接可先核验该帖，不能冒充区域市场比较。评论按需采集，默认不抓全量评论。各阶段支持部分完成和下一轮续采，遇到来源配额优先保留进度，不为达到 50 帖/10 账号目标突破来源上限。

图片需实际查看后描述；不可读取的图片和视频标记未检查，不能臆造朝向、采光、楼层或面积。OCR 数字必须与原图核对。

评论只区分发布者回复、用户提问和未经验证的他人陈述；“还有吗”不是需求成交数，“已出”需确定具体指向。只查看与房源核验有关的内容，不批量收集评论者身份。

## 账号初判

保存角色与独立性两个维度，给高/中/低置信度和引用：

- 个人出租/出售/转租：历史以单套自住房或转租为主、个人叙述一致。标记为“疑似个人”，仅自称房东不升级置信度。
- 中介：持续跨房源发布、经纪身份/门店自述、服务费或带看业务等多项证据。小红书 2026-03 起要求发布房源的机构账号做蓝 V 专业号认证（据媒体报道，需经纪机构备案证书等资质）；主页可见的蓝 V 企业认证、备案证书编号是“机构”角色的强证据，记入 `role_evidence`。未认证的个人号密集发布多套不同房源，记为“疑似未认证经纪”，属于角色核验信号，不是可信度扣分。认证本身也不证明单条房源真实。
- 机构/公寓运营：公开品牌、集中式项目、重复房型库存；同房型可能对应多套房，不能把长时间有房直接判成假房。
- 混合/未知：证据冲突、历史不足或兼有角色。

机构相同、账号互相标明关联、图片水印及文案高度同源等用来建立 `source_group_id`。同机构只视为一个独立来源组；无法确认独立性的账号保留未知，不冒充独立背书。角色不能直接转化为可信度：个人号也可能引流，中介号也可提供充分证据。
